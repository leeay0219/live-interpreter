# 구성 예시

아래 이름과 발언은 모두 가상입니다. 고정 양식이나 반드시 채워야 하는 항목 수로 사용하지 않습니다.

## 짧은 발표

입력:

> 안녕하세요. 소리 잘 들리시나요? 생산 이력과 설비 정보를 ID로 연결합니다. 그러면 불량 제품을 만든 설비와 그때의 작업 조건을 함께 조회할 수 있습니다. 감사합니다.

결과:

```markdown
# 생산 이력과 설비 정보 연결

생산 이력과 설비 정보를 ID로 연결하면 불량 제품을 만든 설비와 당시 작업 조건을 함께 조회할 수 있습니다.
```

짧은 설명 하나로 충분합니다. 결정 사항이나 후속 작업을 새로 만들지 않습니다.

## 제안과 합의가 섞인 회의

입력:

> 조회 시간이 길어지고 있습니다. 캐시를 넣으면 어떨까요? 효과는 아직 확인하지 못했습니다. 논의 끝에 이번 주에는 원인부터 확인하기로 했습니다. 민수가 목요일까지 느린 요청의 로그를 모으기로 했습니다.

결과:

```markdown
# 조회 지연 원인 확인

조회 지연을 줄이기 위해 캐시 도입이 제안됐습니다. 효과는 아직 확인되지 않았습니다.

## 결정 사항

- 이번 주에는 조회 지연의 원인을 먼저 확인합니다.

## 후속 작업

| 할 일 | 담당 | 기한 |
|---|---|---|
| 느린 요청의 로그 수집 | 민수 | 목요일 |
```

캐시 도입은 제안입니다. 합의한 작업으로 바꾸지 않습니다.

## 실제 조치에 영향을 주는 불확실성

입력:

> 조치 대상이 A-17인지 A-71인지 다시 확인해야 합니다. 번호를 확인하기 전에는 해당 설비를 멈추지 않기로 했습니다.

결과:

```markdown
# 설비 조치 대상 확인

## 결정 사항

- 조치 대상 번호를 확인하기 전에는 설비를 멈추지 않습니다.

## 확인할 내용

- 조치 대상이 A-17인지 A-71인지 확인해야 합니다.
```

조치 대상의 불확실성은 본문에 남깁니다. 오인식 교정 과정이 있으면 별도 검토 내역에 둡니다.
